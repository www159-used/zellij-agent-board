# 使用统计：采集事实，汇总后分析偏好

## 原则

采集层记录发生了什么、当时界面是什么状态、执行得到什么结果。次数、比例、耗时、操作路径和用户偏好均在读取日志后计算，不作为埋点字段。数据仍保存在本机，不上传，不生成安装 ID。

访问 ID 每次启动随机生成，仅关联一次看板打开期间的事件。同一本机的长期记录可以按时间汇总；将来如果需要合并多台机器的数据，再讨论是否引入可重置的安装 ID。

## 已实现的 v2 记录

每行有 `v`、`ts`（UTC epoch 秒）、`event`、`visit_id`、`seq`、`elapsed_ms`（单调时钟毫秒）、`app_version`。访问 ID 与序号共同标识事件，关联不依赖日志行的交错顺序。计时从首个 open 事件开始，不包含此前的扫描和终端初始化时间。

| 事件 | 基础字段 |
| --- | --- |
| open | 操作系统；终端初始化成功后记录 |
| state | 列表顺序、Agent 临时 ID、session 临时 ID、CLI 类型、状态、visited；选择位置、终端宽高；搜索/Flash/Picker/帮助是否打开、输入长度、Picker 焦点/位置/匹配索引 |
| input | 键盘或鼠标、映射后的操作名；点击行列、滚动 delta；输入字符统一记 Input，数字前缀统一记 Digit |
| jump | 请求目标的 Agent 临时 ID；请求事件的 seq 用于关联结果 |
| jump_result | request_seq、pipe 返回结果 ok / exit_error / spawn_error |
| close | 关闭原因 dismiss / io_error / panic、持续秒数 |

状态快照只在内容变化时记录。目前每次记录完整状态，不做行级增量，方便独立理解快照。列表 ID 在访问内稳定，不写真实 session 名或 pane ID；不记录标题、目录、搜索文本、prompt。CLI 类型保留适配器工具名称。鼠标移动不逐点记录，但绘制后的相关状态变化仍可能形成快照。

键盘记录的是映射后的操作，例如 Up；暂不区分 j 和方向上键。输入事件保留动作事实，模式进入次数根据 state 的 false → true 推导，避免把输入中的字符误计为功能使用。

## 汇总与分析

`board-tui --stats` 兼容 v1 的历史累计计数，另外从 v2 事件计算：

- 访问数、没有 close 的访问数。
- 键盘/鼠标各操作次数。
- 根据状态变化推导的搜索、Flash、Picker、帮助进入次数。
- pipe 投递结果分布；这不等于实际聚焦成功率。

v2 汇总按访问 ID 与序号排序、去重。缺失 close 的访问不补时长，也不当作零时长。v1 缺少访问关联，不混入 v2 的访问与模式分析。

示例原始序列：打开 → 列表快照 → StartSearch → 搜索打开的状态 → Input → 输入长度 1 的状态 → Confirm → jump → jump_result。

后续读取这些事实可以推导：搜索使用占比、多少 Agent 时开始用 Picker、首次请求耗时、哪个状态的 Agent 更常被选择、模式切换与取消次数。目标偏好需要同时参考当时可选列表；没有跳转的访问可能只是查看状态，不能直接解释为失败。

## 后续工作

- 增加时间窗口、按日期/版本汇总、按 Agent 数比较操作路径和耗时，并明确样本数与缺失覆盖率。
- 查询匹配数目前只有 Picker；补齐普通搜索与 Flash 的结果状态，仍不保存内容。
- 若要区分 j/k 与方向键，增加允许列表中的物理按键枚举，输入模式仍不保存字符。
- 增加日志轮转、流式读取和聚合导出。目前沿用追加 JSONL 与全量读取，长时间采集前应完善容量管理。
- 外部强制关窗可能丢失 close 和投递结果，报告保留缺失；真正聚焦确认需要桥接回执。
- 如需多用户产品分析，另行确定用户主动提供聚合数据的流程；当前实现没有网络发送功能。

## 验证

测试覆盖访问内序号、状态去重、输入与 session 名不落盘、禁用访问、从状态推导模式进入、乱序和重复事件汇总、保留字段不可覆盖、v1 日志兼容。显式 v1 样本位于 `tests/fixtures/usage-v1.jsonl`，混合版本测试确认旧数据不进入 v2 访问指标。宿主测试覆盖键盘搜索/输入/跳转/退出、鼠标跳转、请求与结果关联，以及 IO 错误和 panic 关闭原因；跳转发送函数使用替身，不操作真实窗口。报告将原始 hinting 状态显示为 Flash。真实 Zellij 跨 session 聚焦仍需要交互环境验证。
